# Jessica knowledge base — Q&A set (v1.1)

This folder is the record of the Q&A entries written for Jessica's knowledge base: the voice assistant that answers Mitsubishi / MiDS dealers who call from their Digital Health Analysis report. The live knowledge base is the working copy. This folder is the versioned record, so changes are reviewed and nothing drifts.

**This repository is public.** Entries stay generic: no dealer-specific numbers, no internal identifiers, no prices or contract terms.

## What is in here
| File | What it is |
|---|---|
| `jessica-kb-qa.json` | 71 entries in seven topics: Report basics, Score, Definitions, Findings, Product features, Results, Next steps. Each has a topic, a question and a short spoken answer. |
| `CHANGELOG.md` | One entry per change to the set. |

Not included: four older entries managed in the knowledge base itself (pricing, reimbursement, the Google Business Profile Q&A question, and the three-listings question).

## Rules every entry follows
1. Short: 50 words or fewer, plain spoken sentences, no markdown, no links.
2. No guarantees. Results are described as past results, never a promise. The commitment is go-live in 72 hours after onboarding and results within 90 days.
3. No review-markup claims. Reviews are shown visibly on the page, not marked up in schema.
4. The review campaign is described only as automated emails and text messages sent to past customers to help grow a steady stream of reviews. The phrase "review gate" is never used, and Jessica's instructions say so too.
5. Start-up order: first book a time now, second activate in the MiDS Portal.
6. The local business schema build and delivery are included in the CLIKsearch program, with a full schema analysis consult.
7. The "62%" figure is the year-over-year increase in Google Maps mobile views across 21 Mitsubishi dealer locations, never "62% more local search traffic".
8. Jessica is an AI assistant and says so.

## How to change it
Change the entry here by pull request, add a line to `CHANGELOG.md`, then make the same change in the live knowledge base. If the score method or a report definition changes in `SKILL.md`, update the matching entries in the same pull request.
